## Motivação: o mdc de um intervalo

O problema desta aula:

> Dado um array de $n \le 2 \cdot 10^5$ inteiros e $q \le 2 \cdot 10^5$ perguntas $(l, r)$, responda o **máximo divisor comum** (mdc) de $a_l, \dots, a_r$.

Com $a = 12, 18, 24, 9, 6, 30, 15, 10$ (posições 1 a 8):

| Pergunta | Trecho | mdc |
|---|---|---|
| $(2, 7)$ | 18, 24, 9, 6, 30, 15 | 3 |
| $(1, 8)$ | o array inteiro | 1 |
| $(4, 5)$ | 9, 6 | 3 |
| $(3, 3)$ | 24 | 24 |

Prefix sums não servem: não existe "desfazer" um mdc, do mesmo jeito que não existe "desfazer" um mínimo. Calcular cada trecho do zero custa $O(n)$ por pergunta. Esta aula responde cada pergunta em $O(1)$, depois de $O(n \log n)$ de preparação.

## A ideia, parte 1: blocos de tamanho potência de 2

Pré-calcule o mdc de **todo bloco** cujo tamanho é uma potência de 2: tamanhos 1, 2, 4, 8, … Chame de $T_k[i]$ o mdc do bloco de tamanho $2^k$ que começa na posição $i$. Com o array do exemplo (agora com posições de 0 a 7):

| $k$ (tamanho $2^k$) | $T_k[0]$ | $T_k[1]$ | $T_k[2]$ | $T_k[3]$ | $T_k[4]$ | $T_k[5]$ | $T_k[6]$ | $T_k[7]$ |
|---|---|---|---|---|---|---|---|---|
| 0 (tamanho 1) | 12 | 18 | 24 | 9 | 6 | 30 | 15 | 10 |
| 1 (tamanho 2) | 6 | 6 | 3 | 3 | 6 | 15 | 5 | |
| 2 (tamanho 4) | 3 | 3 | 3 | 3 | 1 | | | |
| 3 (tamanho 8) | 1 | | | | | | | |

Cada linha sai da anterior: um bloco de tamanho $2^k$ é a junção de dois blocos de tamanho $2^{k-1}$, um colado no outro.

$$
T_k[i] = \gcd\big(T_{k-1}[i],\ T_{k-1}[i + 2^{k-1}]\big)
$$

$T_{k-1}[i]$ é a metade esquerda e $T_{k-1}[i + 2^{k-1}]$ é a metade direita. Por exemplo, $T_1[0] = \gcd(12, 18) = 6$ e $T_2[0] = \gcd(T_1[0], T_1[2]) = \gcd(6, 3) = 3$.

São cerca de $\log_2 n$ linhas com até $n$ valores cada: $O(n \log n)$ de tempo e de memória.

## A ideia, parte 2: dois blocos que cobrem o trecho

Para a pergunta $[l, r]$ (de tamanho $L = r - l + 1$), pegue o **maior** $k$ com $2^k \le L$. Dois blocos de tamanho $2^k$ cobrem o trecho inteiro: um que **começa** em $l$ e outro que **termina** em $r$. Como $2^k > L/2$, os dois juntos alcançam tudo, e eles podem se sobrepor no meio:

$$
\text{resposta}(l, r) = \gcd\big(T_k[l],\ T_k[r - 2^k + 1]\big), \quad k = \lfloor \log_2 L \rfloor
$$

$T_k[l]$ é o bloco que começa em $l$; $T_k[r - 2^k + 1]$ é o que termina em $r$; $\lfloor \log_2 L \rfloor$ é o expoente da maior potência de 2 que cabe no trecho.

O traço das quatro perguntas (posições de 0 a 7, então $(2, 7)$ vira $[1, 6]$):

| Trecho | $L$ | $k$ | Bloco da esquerda | Bloco da direita | mdc |
|---|---|---|---|---|---|
| $[1, 6]$ | 6 | 2 | $T_2[1] = 3$ (posições 1–4) | $T_2[3] = 3$ (posições 3–6) | 3 |
| $[0, 7]$ | 8 | 3 | $T_3[0] = 1$ | $T_3[0] = 1$ | 1 |
| $[3, 4]$ | 2 | 1 | $T_1[3] = 3$ | $T_1[3] = 3$ | 3 |
| $[2, 2]$ | 1 | 0 | $T_0[2] = 24$ | $T_0[2] = 24$ | 24 |

Na primeira linha, as posições 3 e 4 estão nos **dois** blocos. Não tem problema, porque $\gcd(x, x) = x$: incluir um elemento duas vezes não muda o mdc.

<Callout type="tente">
Por que essa técnica não serve para **somas** de intervalo? Teste com $a = 1, 2, 3, 4, 5$ e o trecho inteiro $[0, 4]$.

<details>
<summary>Ver resposta</summary>

$L = 5$, $k = 2$: os blocos são $[0, 3]$ (soma 10) e $[1, 4]$ (soma 14). Somando, dá $24$, mas a resposta certa é $15$. As posições 1, 2 e 3 foram contadas duas vezes. A sobreposição só é inofensiva para operações **idempotentes**, em que juntar um valor com ele mesmo dá ele mesmo: mínimo, máximo, mdc, "e" e "ou" bit a bit. Para somas, use prefix sums.

</details>
</Callout>

### Calculando $\lfloor \log_2 L \rfloor$

O GCC tem a função `__lg(L)`, que devolve exatamente o expoente da maior potência de 2 que cabe em $L$: `__lg(1) = 0`, `__lg(6) = 2`, `__lg(8) = 3`. Para não depender dela, dá para pré-calcular um vetor `lg` com `lg[1] = 0` e `lg[i] = lg[i / 2] + 1`.

## Código: o problema da motivação

```cpp
#include <bits/stdc++.h>
using namespace std;

int main() {
    int n, q;
    cin >> n >> q;
    int K = __lg(n) + 1;                                  // número de linhas da tabela
    vector<vector<int>> T(K, vector<int>(n));
    for (int i = 0; i < n; i++) cin >> T[0][i];           // linha 0: os próprios valores

    for (int k = 1; k < K; k++)
        for (int i = 0; i + (1 << k) <= n; i++)           // o bloco [i, i + 2^k) cabe no array
            T[k][i] = gcd(T[k - 1][i], T[k - 1][i + (1 << (k - 1))]);

    while (q--) {
        int l, r;
        cin >> l >> r;
        l--; r--;                                         // entrada 1-indexada
        int k = __lg(r - l + 1);
        cout << gcd(T[k][l], T[k][r - (1 << k) + 1]) << "\n";
    }
}
```

`gcd` vem da biblioteca padrão (C++17). `1 << k` é $2^k$.

**Entrada:**

```
8 4
12 18 24 9 6 30 15 10
2 7
1 8
4 5
3 3
```

**Saída:**

```
3
1
3
24
```

- **Tempo:** $O(n \log n)$ para montar e $O(1)$ por pergunta (contando o `gcd` como uma operação; ele custa $O(\log)$ do valor).
- **Memória:** $O(n \log n)$.

Para **mínimo** ou **máximo**, troque `gcd` por `min` ou `max`. Nada mais muda.

### O mesmo código no formato de contest

```cpp
#include <bits/stdc++.h>
using namespace std;
typedef vector<int> vi;
#define rep(i,a,b) for(int i=(a);i<(b);i++)
void fastio(){ ios::sync_with_stdio(false); cin.tie(nullptr); }

int main(){
    fastio();
    int n, q; cin >> n >> q;
    int K = __lg(n) + 1;
    vector<vi> T(K, vi(n));
    rep(i, 0, n) cin >> T[0][i];
    rep(k, 1, K) for (int i = 0; i + (1 << k) <= n; i++)
        T[k][i] = gcd(T[k - 1][i], T[k - 1][i + (1 << (k - 1))]);
    while (q--) {
        int l, r; cin >> l >> r; l--; r--;
        int k = __lg(r - l + 1);
        cout << gcd(T[k][l], T[k][r - (1 << k) + 1]) << "\n";
    }
}
```

## Armadilhas comuns

<Callout type="armadilha" title="Só para operações idempotentes">
A sobreposição dos dois blocos conta alguns elementos duas vezes. Isso é invisível para mínimo, máximo e mdc, mas quebra somas, produtos e xor.
</Callout>

- **Limite do laço de construção.** O bloco $[i, i + 2^k)$ precisa caber: `i + (1 << k) <= n`. Escrever `< n` deixa de calcular o último bloco válido.
- **Ordem dos índices na tabela.** `T[k][i]` (nível primeiro) deixa a linha `T[k]` contígua na memória e costuma ser mais rápido que `T[i][k]`.
- **Atualizações.** A sparse table é **estática**: se o array muda, ela precisa ser refeita. Para arrays que mudam, use segment tree (milestone 13).

<details class="para-depois">
<summary>Para depois: versão O(log n) para qualquer operação associativa</summary>

**Sem sobreposição.** Para somas (ou qualquer operação associativa), dá para usar a mesma tabela decompondo o trecho em blocos **disjuntos**: as potências de 2 que aparecem na escrita binária de $L$. Cada pergunta passa a custar $O(\log n)$. Na prática, para somas, prefix sums são mais simples; essa ideia de "pular de $2^k$ em $2^k$" volta com força no binary lifting (milestone 16).

**Memória.** Com $n = 2 \cdot 10^5$, são 18 linhas de $2 \cdot 10^5$ inteiros: cerca de 14 MB. Para $n = 10^6$, já são mais de 80 MB.

</details>
